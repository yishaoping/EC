# Performance-Only: CDC Mem + real low-frequency host

Preserves frozen EC 8491167d and Performance-Only baseline 6fada307. Target hardware is exactly the proven 6e1e9b9 Mem candidate; this branch changes build implementation only.

The recipe file is consumed by the deterministic controller. Nominal host frequency 15 MHz (TIMING), fallback 10 MHz (TIMING). The non-project checkpoint flow changes actual MMCME4_ADV CLKOUT0_DIVIDE_F from 24 to 80/120, retaining multiplier4/inputdivider1 and all DDR/PCIe clocks. This is a physical clock configuration change, not a period-only timing relaxation. Actual single-IP tests produced 66.660/99.990 ns derived periods and matching generated Verilog/checkpoints.

Full-shell normalization removes only the identified invalid clock-wizard OOC primary override/jitter and resolves the existing 8 scoped PCIe clock-group commands in their original scope, replaying the same clock sets globally. Every other XDC line is preserved. The original Golden Gate target clock-enable ratio and setup/hold1/0,2/1 remain. Full-shell clock probe is mandatory; no false-path or critical-methodology waiver is introduced.

The already-running Mem DUT synthesis and existing physical candidate are never restarted. Future legacy50MHz candidates defer to the combined Mem version. The new physical owner waits for the existing physical services and holds a separate exclusive implementation lease. CPU quota4 cores, memory144GiB. No concurrent new whole-system implementation.

Order: verified existing full-host/DUT receipts -> real complete-shell post-opt -> resource gate ->15MHz congestion-aware placement/fanout optimization/AlternateCLBRouting -> strict legal-route/setup/hold/pulse/DRC/methodology/bus-skew/clock-coverage gate -> bitstream. A failure saves evidence and tries10MHz with a distinct SLR-spreading placement. No global MUXF remap at95%LUT or narrow-only no-gain candidate is repeated.

Runtime certification remains21-only (0000:21:00.0,21770433G02LA). No device access or model requests occur in these scripts. Native and other experiments are untouched.

The first full-shell replay was rejected after a literal-bracket clock-name lookup failed. The corrected probe uses exact NAME equality filters and checks that every original clock object survives replay; no missing clock group is accepted. The removed 0.033ns internal-input jitter allowance is retained conservatively on the real upstream primary clock. The 10MHz fallback reuses a prior legal15MHz checkpoint when present; only a failed/illegal placement starts a different SLR placement.

The full-shell probe measures 66.640 ns (15.0060024 MHz) at both Golden Gate clock-bridge inputs with the actual DDR-derived reference; the nominal single-IP result above is not substituted for that measurement. The normal 1/0 and 2/1 target clock-enable constraints remain. All seven generated driver/target-description/constraint files match the previous Performance-Only driver inputs byte for byte; this permits a separately bound compatible driver, not reuse of an old hardware certificate.

Future physical results record final per-SLR CLB/LUT/FF/BRAM/DSP/URAM use, SLL counts, setup/hold critical paths, actual clock contracts and report hashes. Completed candidate receipts are reusable without repeating placement. A lightweight deterministic followthrough service observes the existing owner and can recover only the diagnosed corrected-clock-probe wait race before any physical candidate exists. It neither signals healthy tasks nor submits model requests or device operations. Script-generation and failure-path checks are saved separately from the real CAD results.

The five-minute systemd timer `ec-performance-only-progress-watch-r1-20261114.timer` records boot/start-time-bound Vivado CPU, IO, log/phase updates and actual child/service state. A quiet log with active CPU is healthy. Other Vivado activity cannot conceal a stalled process. The watcher resumes an owned stopped process, records thread wait channels for a sustained CPU/IO/log stall, and recovers a vanished owner only from completed synthesis/clock receipts with no live orphan or incomplete physical candidate. It never repeats an unexplained failing strategy.

The complete Mem DUT has finished: 852,986 LUT, 616,520 FF, 563 BRAM tiles, 112 DSP. Relative to the same baseline DUT this saves 86,864 LUT and 311,448 FF, using 18 extra BRAM tiles. These are DUT results, not complete-shell post-opt estimates. The complete-shell job proceeds immediately with the existing proofs; no new simulation gate is inserted.

The isolated future physical job uses eight threads, AltSpreadLogic_high at15MHz and SSI_SpreadSLLs at10MHz if necessary. On a fresh post-opt input it skips unroute/unplace, since no placement exists yet. After placement it identifies only CDC source-valid/allocation nets with at least1024 leaf loads, excludes clocks and ASYNC_REG drivers, and requests slack-independent driver replication (at most16 nets) before ordinary fanout/SLR-crossing optimization. This addresses physical connectivity even when lower host frequency makes timing-driven replication inactive. A route Tcl error still saves the actual routing reports/checkpoint; all legality/setup/hold/DRC gates remain enforced before bit generation.
