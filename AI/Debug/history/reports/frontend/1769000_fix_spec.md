# 1769000 deadlock：证据、根因与基于当前代码的修复规格

日期：2026-10-09。用途：交给 6.1 Sol 独立复核，再据此实施最小修复。

**本文件只是一份设计规格，没有实施硬件修改，没有重新编译、生成 RTL 或仿真。** “Confirmed”用于已有运行的根因证据，不表示下述拟议实现已经通过 Chisel elaboration 或运行验证。

## 1. 必须先读的结论与边界

当前 e4（十六进制 `0xe4`，十进制 228）在 checker 3 的**最早已定位执行偏差是 Frontend 重复交付压缩 `ret`，PC=`0x8000489a`**。同一条动态 ret 被 checker 退休两次，使 checker 的执行计数比 BOOM 对应指令前缀多 1。随后 checker 在最后一条 load 之前达到正确的最终 count，进入 `instruction_tail_waiting`；该 load 的记录已经在 R_LSL，因对应指令不再执行而无法消费。

这与旧 528000 的“BOOM drain 尾部退休漏计、过早发布 final count”不同。当前 e4 的源端最终计数 4074 正确；正常包 checker 的目标计数 4075 包含额外的启动跳转。不能把“4074 对 4075”本身当 bug，也不能用调大 final count、放宽 LSL quiescent、提前 PASS 或提前推进 safe watermark 修复。

需要修正此前不完整的依赖链描述：

- `e4 PASS` 确实依赖 LSL quiescent，e4 dirty-line shadow writeback 确实依赖 `safe >= e4`。
- 但当前剩余的 LSL load **已经送达**。没有证据证明它要等这笔 writeback 才能产生；相反，波形支持它只差对应的 checker 指令消费。
- 因此当前闭合环在 checker 的指令尾部/LSL 内。writeback 等 safe 是下游阻塞放大器，不能虚构一条“最后 LSL 记录等待 writeback”的边。

**最终 Recommended Fix：在现有 Frontend / IBuf / R_BJLR / RocketCore 路径上，明确一次取指交付的有效前缀和 BJL reservation 归属；保存被背压的待发取指片段，只在明确的交付/退休事件推进各自状态。保留现有 GHM DATA/END/count、R_LSL、ICSL tail、barrier/cache/TileLink 协议。**

本规格不采用此前设想的“在 R_LSL 新建内存 replay descriptor，再重建 typed END bridge”方案：它不针对已经确认的 first divergence，而且当前代码已有 END/count bridge。以下所有新增接口均标为“新增”，给出真实宿主与连接点，不把它们冒充现有接口。

## 3. failure、last good、first bad 与 causal chain

### 3.1 终止断言的真实含义

日志为：

```text
[1769000] %Error: BoomCore.sv:6894: Assertion failed ... core.assert__assert_21
```

当前生成 RTL 6894 行是 `assert(~large_0[13])`，注释映射到 `core.scala:1783`；源码为 `assert(!idle_cycles.value(ecWatchdogBit), "Pipeline has hung.")`，`ecWatchdogBit=18`。`WideCounter` 分段后的 `[13]` 不等于源码阈值变成 2^13。

`idle_cycles` 在 BOOM commit valid、CSR stall、RoCC busy 或 reset 时清零。这是 BOOM 长时间没有正常流水线进展的 watchdog，**不是 checker 1 的 assert22**。

### 3.3 完整等待关系

```text
Frontend 将一包的 ret 后缀交付后，又从该后缀重取并交付
  -> checker 多退休一条 ret
  -> 在 BOOM 最后一条 load 之前，sl_counter 已达到 finalCount+1
  -> instruction_tail_waiting=1，停止接纳后续 checker 指令
  -> 最后一条 load 无法进入/通过流水线
  -> 已到达的 LSL head 无法 matching dequeue
  -> lsl.quiescent=0
  -> package_tail_drained=0
  -> package_exec_completion/正常包完成不能成立
  -> 正常退出 instruction_tail_waiting 的条件不成立
  -> 回到“最后 load 无法执行”

正常包不能 PASS
  -> safe watermark 不能连续推进到 e4
  -> e4 dirty-line shadow writeback valid=0
  -> 跨包覆盖 store 被阻挡/重放，LSU/ROB 无法持续前进
  -> checker watchdog 先 CANCEL；CANCEL 不填补 PASS 缺口
  -> BOOM idle watchdog 最后触发 assert21
```

`RocketCore.scala:1422–1446` 的 `package_tail_drained`/`full_check_complete` 与 `R_ICSL.scala:140–165` 的 tail state 构成闭合局部环。`dcache.scala:1057–1060,1205–1214` 构成 safe/writeback 下游链。

### 3.4 root cause 与 broken invariants

源码闭环：

1. `Frontend.scala:188,195–198`：`bjl_redirect_replay` 能让下一次取指回到已锁存的前一分支 npc。
2. `Frontend.scala:259–270,324,452–480`：FQ enq 没有因这种 redirect replay 限制为未重复的前缀；后方 CFI 扫描还能将原本 not-taken 分支所在包改成 taken、bridx=后方 ret。
3. `IBuf.scala:45–64`：`nIC` 仅由 PC offset 和 `btb.taken/bridx` 决定，没有独立的“本次只允许交付几个半字”。只改 mask 不足以修复。
4. `RocketCore.scala:1877`：当前 BJL commit 仅看 WB opcode，不带“这条指令确实 reserve 了哪个 BJL 项”的归属。它不能检测/防止这种重复交付。

破坏的不变量：

- 每条包内动态指令只能进入有效 checker 执行前缀一次；合法循环中同 PC 多次出现不违反此规则，错误重取导致同一动态实例出现两次才违反。
- 一个 fetch transaction 的 **交付前缀、重取/后继 PC、BJL reservation** 必须描述同一条连续执行路径。
- 每个被退休的 BJL-owning CFI 对应一次 reserve 和一次 commit；未 reserve 的管理跳转不能替别人 commit。
- `checker 退休数 - 正常包启动跳转数 = 已重放的源端动态指令数`。最终 count、数据和 ECP 必须对应这个相同前缀。

置信度：重复 FQ 后缀、重复 ret 退休、尾部 LSL 停滞及 safe 阻挡均为 **Confirmed**；将当前首差归为既有前端缺陷、由新时序暴露为 **Highly likely**（位置在未修改基线文件，尚无历史 A/B）。修复后整机可通过仍需新 RTL/仿真证明。

## 4. 与旧修复的关系及排除项

旧 528000 为 seq16（`0x16`）实际 600 条、final 558 条，漏掉 drain 中的 42 条，尾部 5 个 store 无法消费。旧 first-bad 是提前发布 done；当前 e4 finalCount=4074 与源端退休一致，first-bad 是重复前端交付。最新运行的 seq16 已在 FST 547349 附近产生本地结果并继续复用，最终 safe 达 e3；safe 连续推进证明此前包不是仅靠 CANCEL 越过。不能因为序号相同就认定新旧包划分、指令数量仍相同。

保留：稳定 producer owner、drain 全路径计数、真实结束后 final、ordered END、snapshot empty ROB/有效架构 next-PC/注册 quiet、LSL prefetch/稳定 head/匹配消费、result held-valid 和 sequenced release、ICSL 注册 tail、trap/return context 清理、严格 store token、killed-store replay、TtoN/metadata clear、barrier close 与 PASS 分离。

| 假设 | 结论与证据范围 |
|---|---|
| 当前仍是 drain 漏计/15 位 count 截断 | 排除为当前首因：4074 精确且远小于 32768，源端退休对齐支持该 final；不是 528000 的 600/558 |
| 仅 startup +1 算错 | 排除：去掉真实 startup 后仍有额外 ret；该 ret 在 FQ/WB 可直接定位 |
| END 未发送/被 LSL quiescent 卡住 | 排除当前尾部：done/seal 已为 e4；GHM END dequeue 不等 LSL quiet |
| 最后 load 记录尚在 BOOM cache 等 writeback | 排除当前剩余项：LSL 已有对应 head，且此前 load 正常出队 |
| 旧 stale empty-ROB PC 是本次起点 | 不支持：e4 起点到重复 ret 前对齐，first-bad 明确在前端后缀重取；不声称已穷尽所有历史边界 |
| R_LSL SyncReadMem 没读出 head / wrong-type dequeue | 排除为此首因：head valid/payload 存在；停滞缺少合法对应指令，并非匹配错误后强行消费 |
| DCache ready/TL 仲裁不放行导致最早偏差 | 排除：重复 ret 更早；末态是源端 writeback valid 被 safe 条件挡住 |
| 提前放行 watermark/延长 watchdog 可解决正确性 | 排除：都不能撤销已经重复退休的指令；CANCEL 也不能变成 PASS |

这些排除仅针对该 failure 的 causal chain，不替代全设计验证。

## 6. Recommended Fix：交付前缀与 BJL 归属一致

### 6.1 必须修改的文件与最小新增状态

1. `rocket/Frontend.scala`：扩展真实 `FrontendResp/FrontendIO`；checker 路径保存一个待发 response descriptor；按最早 CFI 截断；取指重试不重复 reserve；redirect/包清理使未交付片段失效。
2. `rocket/IBuf.scala`：根据显式前缀长度计算 nIC；半字归属位与 data 同步拼接、缓存、移位；`Instruction` 增加 `bjlOwned`。
3. `rocket/RocketCore.scala`：EX/MEM/WB 同步传递 `bjlOwned`；只为真正退休的 owning CFI commit；驱动包序号、清理请求，将清理完成加入 **result handoff/new-slot admission** 条件。
4. `r/R_BJL.scala`：reserve 只对 resident、真实有效的 head；commit/rollback 同拍使用 post-commit 外层 cursor；checker 的 `bj_s2_replay` 退一项机制不再用于新 descriptor 路径。

`GH_FIFO_SC` 已有需要的内层 post-commit rollback，原则上不必改；可以补局部断言，不改普通 `GH_MemFIFO`。`RocketTile.scala` 的 bulk connect 应自动传递新 IO，仅在实际编译要求补连接时改接线。R_LSL、GHM、R_IC、BOOM cache/LSU 不作本根因的功能修改。

### 6.2 新增字段（名称为实施约定，不是当前已存在）

设 `F=fetchWidth`、`W=coreInstBits`、`P=vaddrBitsExtended`、`S=GH_PACKET_SEQ_BITS=32`。

| 宿主/字段 | 位宽 | 语义、capture/clear |
|---|---|---|
| `FrontendResp.prefixLength` | `max(1,log2Ceil(F+1))` | 从该 response 的 PC offset 开始允许交付的半字/指令槽数量；随整个 response 持有，FQ fire 消费 |
| `FrontendResp.bjlEndMask` | F | 仅在 **已 reserve CFI 的最后一个槽**置 1；每 response 最多一个 1；普通/管理/异常 response 为 0 |
| `Instruction.bjlOwned` | 1 | 展开后的这条完整指令拥有一项 reservation；由最后一个有效槽的 mask 导出，不从 opcode 猜测 |
| EX/MEM/WB `*_bjl_owned` | 各 1 | 与该级指令采用完全相同的 capture、kill、replay、valid 条件；bubble/被杀指令为 0 |
| Frontend descriptor `state` | 枚举 | `EMPTY/FETCHING/CLASSIFY/WAIT_BJL/READY_TO_EMIT`；仅一个待发片段 |

| descriptor `reserved,npc,taken` | 1/P/1 | 只在 reserve fire capture BJL head；与 descriptor 一起保持，不根据后来 head 改写 |
| descriptor `nextFetchPC` | P | 本片段实际交付后的后继；含 CFI 时来自所捕获记录，否则为未交付后缀起点/下一 block |
| 请求 S1/S2 owner-valid、seq | 1+S | 由真实 ICache request acceptance 对齐，响应只能 capture 到仍有效的同一请求；redirect 清 valid |
| checker partial `valid,bits,pc,seq` | 1/W/P/S | 仅在 FQ fire 交付末尾不完整 32-bit 指令低半字时更新；正常顺序续取保留，redirect/清理丢弃 |

| `FrontendIO.checker_clear` | Output Bool | core 寄存的包级清理请求，保持至 ack；不是 combinational full_check_complete |

descriptor.valid 可由 state 派生，不额外复制一个可不一致的 valid。`reserved` 可编码进 READY 子状态；保留名称是为定义 invariant，不要求重复存储。identity 由 seq、请求级 valid 和真实 redirect kill 保证；**不必新增无限增长的 replay token、跨 CDC epoch 或通用 transaction manager**。

不能只存一个 `RegNext(BJL.peek)` 或只保存 `replay_pc_cfi`：它们不能证明当前 ICache data、reservation 和 FQ 交付仍属于同一请求。

### 6.3 前缀规则：不混用“截断”和“taken”

IBuf 修改前有：

```text
start = pcWordBits
legacyEnd = btb.taken ? btb.bridx+1 : F
legacyNIC = legacyEnd-start
```

新增后，非 checker response 的 `prefixLength=legacyNIC`，`bjlEndMask=0`；checker response 的 `nIC=prefixLength`。可以统一让全部 response 使用 `nIC=prefixLength`，但 legacy producer 必须逐项保留原取指语义。

合法范围为 `0 < prefixLength <= F-start`（异常/replay response 也必须按现有异常交付规则给出可被 IBuf 消费的槽，不生成永远无指令的 zero-length valid）。`mask` 同步只标记本前缀，但 **IBuf 不能继续忽略 prefixLength 而只读 btb**。

- 最早完整普通 CFI 有 BJL：只交付到该 CFI 的最后一个槽，即使它 not-taken；后面的第二条 CFI 不在此 response 中执行。
- 无 BJL 而 CFI 前有完整普通指令：先交付那些指令，再从 CFI 起点取指等待。否则把早于该 CFI 的 load 留在 descriptor 中，可能造成“等后方 BJL 到达、而 DATA 被前方未消费 load 填满”的新环。
- 无 BJL 且 CFI 已是第一条完整待交付指令：WAIT_BJL，保持 data，不 dequeue，不伪造 target。
- 无完整 CFI：可交付连续有效前缀；末尾只有 32-bit 指令低半字时允许按现有 IBuf 拼接协议交付低半字。
- 特殊管理 JALR、取指异常/replay 不等待一个不存在的 BJL 项，见 6.6。

e4 例子：第一次只发 PC=`0x80004898`、`prefixLength=1`、`bjlEndMask=01`、taken=false；`nextFetchPC=0x8000489a`。第二次从 `0x8000489a` 开始、prefixLength=1、bjlEndMask=10，交付 ret 后跳向其 BJL npc。两次访问可以读相同 cache word，**有效半字集合互不重复**。

### 6.4 descriptor 状态机与 exactly-once

| 状态/事件 | 动作 | 后继 |
|---|---|---|
| EMPTY，可发 checker 请求 | 锁存 PC/seq，拉 request valid，直到 ICache req.fire；owner valid 按真实 fire 进入 S1/S2 | FETCHING |
| FETCHING，TLB/I$ miss 或需原地重试 | 保持同 PC/seq，等本次请求阶段结束后重试；没有完整 response 前 **不 reserve BJL** | FETCHING |
| FETCHING，合法 response/exception | capture 完整 response 及异常信息；清该次 request owner-valid | CLASSIFY |
| CLASSIFY，无需 BJL或可先发 CFI 前缀 | 固化 prefixLength、endMask=0、nextFetchPC、partial 更新描述 | READY_TO_EMIT |
| CLASSIFY，最早 CFI 需 BJL | 锁存 CFI 身份；只接受 exact PC/长度匹配的 head | WAIT_BJL |
| WAIT_BJL，resident head 匹配且无 kill | `bj_req_valid && bj_req_ready` reserve 一次；capture npc/taken，置 reserved，形成响应 | READY_TO_EMIT |
| READY_TO_EMIT，FQ 不 ready | valid 持续、bits 不变；不再次 reserve，不推进 PC，不改 partial | READY_TO_EMIT |
| READY_TO_EMIT，fq.enq.fire | 交付一次；更新 partial/后继 PC；descriptor 释放；reservation 归属随 response 移交 FQ | EMPTY |
| 任意状态，core redirect/flush | 取消未交付 descriptor/request owner/partial；FQ 沿现有 req.valid reset；BJL rollback 到 post-commit 点；下一请求用 req.bits.pc | EMPTY/FETCHING 新路径 |
| 包清理 | 按第 8 节作废旧 checker 状态，禁止再从该 seq reserve；不杀正在执行的管理/异常处理路径 | 完成后 EMPTY |

ICache 接口是 Decoupled request、固定流水 response，miss 不保证以后对原 request 发一个额外响应；因此 FETCHING 不能写成“只等 resp.valid，永不重新发请求”。沿用真实 TLB/ICache S1/S2 miss/retry 语义，按实际 `icache.io.req.fire` 对齐身份，保留 guest fault GPA sideband（延迟 FQ enq 时 GPA 也须与 descriptor 一起持有或在原响应接受点按同一身份锁存）。

FQ 是 `flow=true`，必须保证新 checker `enq.valid` 来自 READY 寄存状态。不得继续用旧 `s2_replay = !fq.enq.fire ...` 去反向控制该 valid 或当前 reservation。非 checker 路径保留既有结构，两条路径由请求 capture 的 owner/mode 选择，而不是让 live mode 切换重新解释一个旧 response。

请求的 replay 属性在发起时锁存：至少要求 `checker_mode && !if_check_completed && !checker_clear`，且有合法非零 checker_seq；特殊启动 JALR 则在指令分类时明确豁免 BJL。这里的 `if_check_completed` 是当前 FrontendIO 的后检查阶段指示。进入 postchecking/clear 后的新管理返回取指走普通前端路径，即使 live checker_mode 仍为 1，也不能进入 WAIT_BJL。已有 checker descriptor 不因这个 live 属性改变而重新解释为普通包；它只由原交付事件或 redirect/clear 处理。

**exactly-once 分三个阶段：**

1. BJL reserve：在 WAIT→READY 一次；miss/等待 FQ 不做重复 reserve。
2. Fetch emit：在 READY 的 FQ fire 一次；之后 descriptor 不再拥有这份 payload。已经交付的半字只能因合法架构 rollback 被重新取到，不能在同一未回滚执行路径重复交付。
3. BJL commit：携带归属的 CFI 在 WB 真正退休时一次；reserve 并不等于不可撤销 dequeue，emit 也不等于 commit。

### 6.5 IBuf 归属拼接和 RocketCore commit

`bjlEndMask` 与数据采用相同的 offset/shift/concat；缓存到 `buf` 时必须按 `shamt` 移位，后续移动 `buf.data` 时也移动它。不能把整包的 reserved bit 复制给每条指令。

- RVC 的 `Instruction.bjlOwned=combinedEndMask(j)`。
- 32-bit 的 `Instruction.bjlOwned=combinedEndMask(j+1)`，仅 full instruction valid 时有效。
- 跨 block 的 32-bit CFI：低半字已在 IBuf，归属位在下一 response 的高半字，拼接后恰好属于这一条指令。两个半字不能各 commit 一次。
- kill 清除 nBufValid 和归属有效性；异常/replay 槽不产生可退休 reservation 标记。
- ID capture 条件沿用 `!ctrl_killd`；MEM、WB capture/kill 与现有 `ex_reg_valid/mem_reg_valid/wb_reg_valid` 同步。

`io.imem.bjl_commit` 改为 `wb_valid && wb_bjl_owned`，并断言该指令为普通 CFI；保留 `wb_valid` 已包含的 replay/exception/check_exception 排除条件。不得用 `wb_reg_valid` 或 `csr trace.valid` 的不同延迟层替代。

### 6.6 CFI、跨块、特殊指令与异常的覆盖

1. CFI PC 使用准确的指令首地址；BJL is_rvc 必须匹配指令长度。删除新 checker 路径的 `PC 相差 <=2` 近似匹配，跨 block 情况由 partial.pc 明确表示。
2. 同 cache word 两条 RVC CFI：第一条单独形成前缀；第一条 taken 时后缀永不交付，not-taken 时后缀在下一 descriptor 交付。第一条/第二条 BJL 晚到均可等待，不能借用对方记录。
3. 32-bit CFI 的低半字在 block 末尾：低半字可先交付，partial 只在该次 FQ fire 更新；读取下一 block 后重组识别，在高半字前等待匹配 BJL。若高半字为 page/access/guest fault，按原异常路径交付，不等待正常退休分支记录。
4. 后方的特殊 JALR 不能让前方普通分支跳过 BJL；`isSpecial` 必须属于当前最早 CFI，不能用整包 `specialJalrVec.orR` 作全局豁免。
5. 当前管理 ISA 的 bit12=1 JALR：`Instructions.JALR` 的 BitPat 允许该编码；`RocketCore.scala:696,732` 在 checker 模式使用 rsu_pc，并由 MEM 发 redirect。这类 checker 本地启动/管理跳转不属于源程序的 BJL 流，发出时 endMask=0、不 reserve、不 commit；它仍计入正常启动的 +1。不能等待 BJL 才执行启动跳转。
6. 普通源程序 CFI 由 `boom/trans/GH_BUF.scala:92–138` 按架构提交产生记录。特殊管理编码不应作为普通源端目标指令混入该流；独立核实软件中此编码的用途，若发现源端也对同一特殊指令产生待消费 BJL，必须先报告协议前提不一致，不能静默忽略该项。
7. 中断/异常/重放：只在真实 core redirect 时 rollback，不能仅因暂时非 checker_mode 清除已到达但未消费的 BJL；handler 不拥有包内 reservation。xRET 返回后用保留的 committed point 重放被杀前缀。

### 6.7 R_BJLR 游标的同拍优先级

选用 resident-only reserve：`bj_req_ready` 对外采用当前 spec bank 的实际 `peek_valid`，不把单纯 `enq_valid` 当成已接受 head。新 frontend 不依赖入队旁路，最多增加一个等待拍；CDC 输入和既有 nearfull/headroom 不被关断。

```text
commit_fire = bj_commit_valid && can_commit(commit_bank)
commit_after = commit_fire ? incBank(commit_bank) : commit_bank
reserve_fire = bj_req_valid && bj_req_ready && !rollback && !clear
commit_bank_next = commit_after
spec_bank_next = rollback ? commit_after : reserve_fire ? incBank(spec_bank) : spec_bank
```

所有 bank rollback 使用已有 `GH_FIFO_SC.cptr_after_commit`；外层必须使用同一个 post-commit 语义。commit 可以与 redirect 同拍：先保留本拍真正退休的最老项，再撤销更年轻 reservation。不能先全清后让已经退休的项被 reserve 第二次。

新 checker descriptor 在取到完整 response 后才 reserve，所以 `bj_s2_replay` 退一项不再参与这条路径，明确接 false；不能同时保留旧 S1 reserve/S2 decrement 和新 descriptor reserve 两个所有者。其他调用点若存在，先逐个核对，不改其未确认语义。清理/reset 期间禁止 reserve；清理不能与合法旧 CFI commit 并发，若出现应报 invariant violation。

## 7. DATA / END / count：保留已经存在的表示

当前 `GHM.scala:224–295,309–378` 已实现：

| 层级 | 表示与事件 |
|---|---|
| 源端计数 | 每 slot 16 位：bit15 done，bits14:0 count；seq 单独携带 |
| DATA CDC | `Cat(isEnd:1, seq:32, payload:dataPayloadBits)`，同一 AsyncQueue |
| END payload | 低 15 位 finalCount，上位 pad，不把 END 当一条指令或一条 load |
| live control CDC | seq + 15 位 liveCount + 原控制字段，由 `countCtrlBits` 派生宽度 |
| checker count | `GH_CHECKER_COUNT_BITS=53`：bit52 valid，bits51:20 seq，bits19:16 reserved，bit15 done，bits14:0 count |
| RocketCore→ICSL | 先以 bits51:20 匹配 package_seq，再将 bits15:0 传入 ICSL；不是把 seq 截掉后盲用 count |

生命周期：source seal 与 final 到达后 capture `end_pending/end_seq/end_count`；真实 DATA/anchor 先行；END valid 保持到 `u_data_cdc.enq.fire && send_end`；END dequeue fire 更新 checker `receivedCount.seq/count/done`，匹配 final 后旧 live progress 不得撤销 done 或回退 count。END 不写 R_LSL/BJL，deq.ready 不以 LSL quiet 为前提。

本轮不重新拓宽 bridge，也不改变 `GH_TOTAL_INSTS=5000` 或 drain headroom。必须保留 `N+1` 用 16 位 checker 运算的空间；4074 的证据不等于所有阈值角落均已验证。源端 count overflow/final 小于 live 的检查继续保留，不能用饱和或截断掩盖错误。

这不是声称现有所有 CDC 角落都已证明安全；是明确它们不是本 first-bad 的缺失机制。若独立审核发现当前 bridge 与以上源码不同，应先停止并报告版本差异，不按本文凭空补第二套 bridge。

## 8. per-slot 生命周期与前端清理对接

不新建一套替代现有 package FSM 的多 slot 管理器。以下逻辑状态由 RocketCore 已有寄存器组合表示：

| 阶段 | 现有状态/事件 | 保持与退出条件 |
|---|---|---|
| 可分配 | `package_ready_for_new`、context idle、无 result/cleanup pending | `new_package` capture seq；不得因 END/新 anchor 到达而覆盖旧 owner |
| 已拥有、待启动 | `package_start_pending`，可能 count/END 先到 | CPS/COPY 或 privileged start 接受；已匹配 count 不在 start 时丢失 |
| 正在执行 | `package_check_active`、ICSL checking/priv | 每条指令/记录按正常规则进展；前端 descriptor 归属固定 seq |
| 指令尾部等待 | ICSL 注册 `instruction_tail_waiting` | 必须真实执行完整最终前缀后才能进入；继续允许已有效 EX/MEM/WB 尾部排空 |
| 后检查 | `package_exec_done`、ARF/CSR 比较 | 不增加“FQ/descriptor 必须空”作为 exec_done 前提；可以存在超出包尾的 speculative fetch |
| 结果本地 capture | `package_result_fire`、waiting/queue | status/seq held until result handoff；这一事件不是 BOOM release |
| 清理 | `package_cleanup_pending`、context_idle、RSUSL/LSL idle | 增加前端旧上下文 clear ack；return/trap 清理和 result 传输仍分离 |
| 结果交接/复用 | `package_result_handoff_fire`，GHM result CDC，BOOM sequenced release | local cleanup 完整且旧 result 已交接后，才允许新 seq |

新增前端清理状态只需要：core `checker_clear_pending` 和 frontend 寄存 ack；必要的前端旧路径标志由请求 owner-valid/descriptor 和一个“本包 checker fetch 已发出且尚未被 redirect kill”的 sticky bit表达。

具体规则：

1. `checker_clear_pending` 在 **RegNext(package_result_fire)** 对应周期置位，随旧 seq 保持至 `checker_clear_done`；不能把 `package_cancelled` 组合接 BJL reset，避免错误输出→reset 的环。
2. normal result 要求执行尾部/ARF/LSL 已完成；此时无合法旧 CFI 可再退休。cancel 则先使用现有 cancellation/trap return 路径杀掉旧 checker 执行，不强行抢占 handler。
3. frontend 接到 clear 后禁止旧 seq 再 reserve，清 BJL bank 状态和未交付的旧 checker descriptor；普通 handler/管理取指可继续。**不能无条件 reset 全 FQ/IBuf 而不给 handler redirect PC**。
4. 已交付 FQ/IBuf 的旧 checker 路径由真实 `io.cpu.req.valid` 和现有 `ibuf.kill := take_pc` 清除。包正常返回到 pc_special、异常入口、取消返回都已有这条 redirect 路径；clear ack 必须等该旧路径确实被 kill，及旧 S1/S2 owner-valid 已失效。若 clear 时正处在 checker 流且尚未 return redirect，则保持 pending，等现有返回；不要新增“先 ack 才允许返回”的条件。
5. 追踪旧路径的 sticky bit在属于 checker replay 的请求被接受时置位，在 core redirect 时清除旧路径；如果同拍接受了新路径的 checker 请求，则新的标志按该请求重新置位，不能被旧路径 clear 覆盖。postchecking 的管理返回目标 fetch 不重新置位。request 必须按 capture 的 replay/管理属性区分，不能仅用 live checker_mode（postchecking 仍为 checker mode）。`io.imem.if_check_completed` 当前正由 ICSL state 6/7 驱动，可用于此区分；它表示后检查阶段，不能误当已有 PASS。
6. BJL 当前 `withReset(reset || if_check_already_done)` 必须改为上述明确的包清理/reset。`R_ICSL.already_done` 在普通包 `sl_counter>=N` 就成立，而真正边界是 N+1；最后一条如果是 CFI，提前清空会造成新死锁。不能以“只差一条”作为安全依据。
7. 在 slot 空闲 ack 初值为 true；新包 capture 后撤销。ack 仅对旧 checker 上下文负责，**不要求整个 frontend/FQ 在管理循环中一直为空**。将寄存 ack 加入 `checker_local_cleanup_done`/`package_result_handoff_allowed` 和下一包 admission，不加入 `package_tail_drained` 或 ARF 比较/exec completion 的前置条件。
8. 取消过程中如果 handler 尚未 matching xRET，现有 `icsl.context_idle` 继续阻止 slot 复用；ack 不能代替 trap_depth/return_pending。旧 END/record 的迟到处理沿现有 seq 协议，不在前端绕过。

关键无环关系：`full_check_complete → result本地capture → clear_pending`；管理返回由既有 completion/cancel 驱动，**不等 result handoff 或 clear ack**；随后返回 redirect 清旧取指状态，ack 允许 result handoff/slot reuse。这条链没有回到 exec_done 的依赖边。

## 9. 为什么能继续 forward progress，且不靠绕过协议

在合法源流、CDC/TL 最终响应且各时钟继续运行的既有公平性前提下：

1. 取指 miss 只重试同一未交付请求，不持有错误 BJL reservation；完整 response 一旦到达就可分类。
2. 完整普通前缀先交付，使早于当前 CFI 的 memory/CSR/RoCC 请求能消费记录、释放 DATA 通路。最早需 BJL 的 CFI 等的是其源端已退休记录，不等自身 checker PASS。
3. reserve 后不再依赖 BJL 下一个 head；FQ 暂满时 descriptor 保持。FQ ready 后发一次，下一取指从实际未交付后缀或正确 target 开始。
4. 后方 BJL 记录不会被前方 CFI 或管理跳转误 commit；真实 redirect 保留已 commit 前缀，只回滚被杀的 reservation。
5. e4 因而少掉额外 ret，在应执行最后 load 时计数尚未耗尽。load 正常请求 LSL、match、dequeue、WB 一次，随后达到 4075、LSL quiescent，原 completion gate 可成立。
6. ARF/CSR、result、连续 PASS、安全 writeback 按原协议完成；不移动 barrier ACK/PASS 边界，不改变 C-channel permission 或 metadata-clear 次序。

这证明修复在机制上移除了当前死锁的可达前提；不是从一个已经重复退休、寄存器可能已损坏的现场强行恢复。无法保证任意坏源流、丢失外部响应或永久 backpressure 下“无条件进展”，也不能把 watchdog CANCEL 作为本修复成功标准。

## 10. 风险收敛与不允许的实现捷径

| 风险 | 分类/处理 |
|---|---|
| 只给 `fq.enq.valid` 加 `!bjl_redirect_replay` | 不采用：可能丢掉已经 reserve 的前一条分支，并让 fire/replay 互相依赖 |
| 只改 mask 或用 taken=true 冒充前缀截断 | Blocking，已在方案消除：新增 prefixLength 并修改真实 IBuf nIC；taken 保留真实语义 |
| descriptor 等 BJL 时扣住前方可执行 load | Blocking，已消除：先交付完整非 CFI 前缀，不等未来记录 |
| 先在 S1 reserve，再遇 ICache miss/S2 retry 重复退项 | Blocking，已消除：完整 response 分类后 reserve；取消新路径的 bj_s2_replay |
| 每发一条分支都等它 WB 后才发下一条 | 不采用：现有 count/overtake 依赖流水线进展，且没有必要增加此等待 |
| 跨 block 指令把高半字当新 RVC；partial 在等待时改变 | Blocking，已消除：partial 按 FQ fire 更新、保存 PC/seq；完整重组后匹配 CFI |
| commit+rollback 外层/内层游标不一致 | Blocking，已消除：两层都使用 post-commit cursor |
| special JALR 等不存在的 BJL、或错误 commit 下一项 | Blocking，已消除：保留真实管理跳转路径，归属位为 0；软件用途是实施前明确复核项 |
| 提前 already_done reset 丢最后 CFI | Blocking，已消除：真实包清理替换提前 reset |
| 清理等全 frontend idle，管理循环永不空 | Blocking，已消除：ack 只清旧 checker 路径；不阻止管理 return/handler |
| cleanup_ack 又进入 exec completion，形成新环 | Blocking，已消除：仅用于 handoff/admission，不接 tail/ARF/exec gate |
| CDC 新多位裸同步、END 等 checker PASS | Ruled Out：本轮不增加跨时钟 payload，不改已存在同队列 END |
| Scala 编译/API/宽度/初始化、实际 FIRRTL 组合环 | Acceptable Risk 仅指设计可实施；必须真实编译/生成后才可判 PASS |
| 非 checker BTB/RAS、I$ miss、guest fault、ITIM、时钟门控 | 动态验证风险：保留原路径和 sideband；不能因当前测试未用就漏连 |
| barrier 开关、特权/异常、slot 快速复用的整机回归 | 动态验证风险：需对应 RTL 实跑；当前证据不覆盖所有组合 |

具体 Chisel/FIRRTL 约束：

- Bundle 新字段全部赋值；非 checker 默认值必须合法；检查所有 `new FrontendResp/Instruction/FrontendIO` 使用点。
- prefix/end index 用足够宽 UInt，`bridx+&1`/加减法先扩展再截取；参数 F=1 时不产生 0 位寄存器或负 slice。
- 无 `fq.ready → enq.valid → fq.fire → replay → enq.valid`；无 `commit.valid → snapshot → gh_stall → commit.valid`；无 `LSL empty → checker stall → pipeline valid → LSL/tail` 新反馈。
- reserve valid 由寄存 state 和 stable head match 导出，commit 由寄存 WB 归属导出；resident-only head 不把同拍 enq/full/commit 反馈引入 payload 匹配。
- redirect 优先于 emit/reserve；真正已退休 commit 与 redirect 同拍保留；局部 clear 延后一拍并持有。每个寄存器一个明确优先级，不能依赖分散 `when` 的最后连接碰巧胜出。
- FQ/IBuf/partial data 和新 metadata 同时 kill、同时 shift；GPA/fetch exception 不使用后来 S2 的值。
- gating clock 要把 descriptor/request/clear pending 纳入唤醒/保持条件；不要把 ungated BJL pulse 交给睡眠中的状态机。当前 might_request 常开也不能代替结构正确性。
- `dontTouch` 只作用于命名 Wire/Reg，不直接作用动态 Vec/Memory 选择，避免历史 FIRRTL target parser 错误。

## 11. 实施顺序与验收

### 11.1 实施顺序（每步都以当前工作树为底座）

1. 独立重放第 3 节证据，确认生成 Frontend/IBuf 与当前源码语义对应，记录软件二进制身份；不要先修改 cache/LSL。
2. 先落 `FrontendResp.prefixLength/bjlEndMask` 与 IBuf 拼接、Instruction 归属及 RocketCore stage 传递；未切换新 frontend 时 legacy producer 填原 nIC，归属为 0。整个补丁未完整前不能运行“半迁移的 BJL commit”。
3. 实施 descriptor、prefix/partial、response 身份、reserve/emit 事件；将旧 checker replay/reserve 逻辑整体切换到新唯一拥有者，保留非 checker 路径。
4. 实施 R_BJLR resident reserve 与 post-commit rollback；接 WB-owned commit、包 clear/ack；替换 already_done reset，复核正常/priv/exception/return。
5. 审查整体 diff：只能包含前述必要模块，已有 528000/drain/LSL/seq/cache 修改不回滚；确认新字段接线完整。
6. 实际 Scala compile，随后目标 v1Config elaboration/FIRRTL 环检测/初始化检查与 RTL 生成。只做 scalac/parser 或静态脚本不足以验收。
7. 定向仿真再完整 benchmark；先判断 first divergence 是否消失，再看是否越过 1769000。

### 11.2 必须验证的定向矩阵

- 两条 RVC CFI 同 word：first taken/not-taken、BJL 首项/次项迟到、FQ backpressure、第二项在 enq.fire 同拍到达。
- RVC+普通指令、普通指令+CFI、32-bit CFI aligned/跨 word/跨 page；高半字 fault/replay；partial 后遇 redirect。
- ICache miss/TLB miss/FQ full；ready 间歇；验证 pending payload 稳定、reserve/emit/commit 守恒。
- WB commit 与 redirect 同拍、WB replay、MEM special JALR、sfence、interrupt、matching xRET；不会重复 rollback/decrement。
- 最后一条为 CFI/跨 block CFI/普通 load/store，N=0/1/最大合法值；尾部 END 早于/晚于 CPS/live count。
- cancel 在 WAIT_BJL/READY/FQ/handler 中、clear 延迟、快速 slot 复用；旧 seq 不可进入新包，handler 取指不被无目标清空。
- GHM DATA 多 lane 原子接收、CSR/RoCC/AMO、END 顺序和 count 精确性均维持。
- barrier 开/关对应软件/RTL；检查 TtoN、writeback/meta-clear、safe 只由连续 PASS 前进、store token 一次性。

### 11.3 针对本次 failure 的通过条件

1. 同一 e4 类似指令序列中，`0x80004898` 与 `0x8000489a` 的交付前缀不重叠；ret 仅一次有效退休（包划分/时间变化时按动态指令对齐，不能硬编码 seq=e4）。
2. 以 BOOM ROB 架构退休流作为独立 scoreboard，扣除合法 startup 后逐项比较 checker PC/机器码；不能用改过的 count 自证正确。
3. 最后一条 load 实际到达 LSL match/dequeue/一次 WB，所有响应生命周期结束后 quiescent 才高。
4. matching END/final、ECP/CSR、exec done、PASS、result handoff、BOOM release、safe、合法 writeback 全链完成；不把 CANCEL 清理当进展。
5. 旧 snapshot 无并发退休/架构 next-PC 正确、LSL head 稳定/不误 dequeue、drain count、barrier/TL/token invariants 同时成立。
6. 完整程序输出正确；越过原 watchdog 时间仅是中间条件。

## 13. 必须项、可选项与交接结论

必须项是显式交付前缀、单 descriptor 持有 payload/身份、CFI 完整匹配、BJL 归属随指令到 WB、跨块和管理跳转处理、post-commit rollback、真实包生命周期清理，以及实际编译/生成/仿真。

可选优化是同 word 后缀缓存避免再次访问 ICache、多个待发 descriptor、BJL enqueue bypass、同拍 reserve+emit、批量多 CFI 交付、额外性能计数器。**本轮不实施这些优化。**

R_LSL 内存 replay descriptor、第二套 count/END bridge、重写 GHM/per-slot 总 FSM、改变 safe/barrier/TileLink 条件均不是本 root cause 的必要修复，不应混入补丁。

本规格已把正常路径和必要 corner case 映射到当前实际模块，适合开始独立核实与实施。仍须首先核对特殊管理 JALR 的软件用途、ICache 实际 latency/GPA 保持、清理返回与旧路径 kill 时序；若真实代码不满足本文逐项前提，应报告具体不一致，不能强行套用。任何“已安全通过”结论必须等真实 elaboration、FIRRTL 与新运行证据，不能从本文件的静态设计推导为已验证事实。
