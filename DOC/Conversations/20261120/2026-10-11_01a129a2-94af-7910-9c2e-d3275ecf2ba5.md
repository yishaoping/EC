## Key design decisions in new document

**Single resident version + unified admission + ordered save confirmation**, reuse existing WB/RPQ/SDQ/LineBuffer/TL Release/Acquire. No permanent per-line multi-version data array.

### Metadata

Separate **request_seq** (instruction/package attribution) from **content_seq** (current complete line image owner). Loads/MSHR max request seq must not change data identity.

L1:
- existing tag/coh/way
- `content_kind` = BASE / OWNED / UNKNOWN; content_seq
- `parent_seq` = validated predecessor identity for current version
- `lower_equal` one-bit certificate: **current full image exists in L2**
- `generation` for identity changes/invalidate/way reuse
- transient owners live in existing MSHR/WB/prober descriptors + one version coordinator slot replacing loose crossPackage pending flags.

Safety derives from **functional continuous validated watermark**, does not clear seq when safe.

Important `lower_equal` nuance: after pushing P and reacquiring P, fresh Grant proves L2 already contains P. First Q store consumes this certificate, avoiding infinite release/reacquire/push cycles. Dirty safe P with no current certificate must physically push. Any actual store clears certificate, same package included.

L2:
- content_seq/parent_seq
- `parent_in_dram` (spec version’s predecessor saved)
- `outer_equal` (current full resident image saved to DRAM)
- these bits cannot merge; P becoming safe still needs current P saved before Q overwrites.

### Unified admission and pipeline

One `version_admit` for LSU, replay, SC/AMO and owner transitions.
- same-package write fast path
- different version: old safe + valid lower copy required
- UNKNOWN / owned seq0: fail closed
- new_seq < current seq: duplicate completed token may ack; otherwise ordering bug, do not “wait newer safe then apply older”.
- S2 uses effective provenance forwarding from older S3 writes to avoid back-to-back old metadata race.
- S2 grants short-lived write authorization, owner cannot invalidate/refill until actual write or cancellation.
- lock begins before clear; stop new conflicting requests, drain prior accepted pipeline work, metadata recheck, then snapshot/clear/refill.
- clear alone does not unlock.

### Replay/LSU ownership

Current RPQ dequeues and SDQ frees at replay issue; design changes:
`RPQ head → admit/issue → inflight → actual write/response → replay_done(id,token,generation) → pop + SDQ free`.
One inflight replay per MSHR; no simple post-dequeue S2 nack that loses request.

For minimal implementation:
- MSHR write-domain contains **one package**; cross-package secondary writes rejected/nacked to STQ.
- Once store miss/upgrade is accepted by MSHR, LSU stops issuing **younger stores** until this token physically completes. Hit stores still pipeline, loads proceed. This prevents dynamic P→Q→P mixed line.
- functional `store_apply_done`/STQ allocation token independent of traffic measurement. Early miss acceptance response ≠ physical store completion.

### L1 state machine

`Observe → WaitSafe → FreezeDrain → Recheck → CaptureSend → WaitSave → Clear → HandoffRetry`

- old-safe enters same flow skipping wait.
- WaitSafe does not occupy WB/data arb; permits required older work/probe progress.
- freeze/drain then full snapshot.
- reuse `ReleaseData(TtoN)` with correct actual coherence shrink.
- `wb.resp` means snapshot done, not data saved.
- late matching L2 ReleaseAck is save-done.
- clear + hazards drain + ownership handoff, then original Q retries via STQ/miss/refill.

- MSHR exclusive destination owner, full line install atomic provenance; remove per-beat clear.

建议采用 **单份 resident data＋统一版本准入＋有序保存确认**，复用当前 BOOM/Rocket pipeline、WB、MSHR 和 TileLink 通道。

**1. L1 metadata 与统一 ownership**

每条 line 保留 `content_kind/content_seq`、`parent_seq`、`lower_equal` 和 `generation`；瞬态 owner 放在现有 MSHR/WB/prober descriptor 与一个 version coordinator 中。

`request_seq` 与数据所属的 `content_seq` 必须分开。safe 由连续 validated watermark 判断，validation 不清除版本身份。

普通 `t_lsu`、`t_replay`、成功 SC/AMO 使用同一 admission gate：

- 同包写：正常覆盖。
- 跨包写：旧版本必须 safe，且当前完整旧 image 已保存到 L2。
- owner 冲突或 generation 过期：不得成功写入。
- 尚未完成的旧包 replay：不能在新版本之后继续写回。

clear/refill/WB 捕获必须先取得 owner、阻止新冲突请求，再 drain 已获准的流水线操作，重读 metadata 后执行。clear 完成不能直接解锁。这对应已有 `432471 clear → 432475 store → 432527 refill 覆盖` 的数据丢失证据。

**2. L1 push-before-overwrite 与 replay 完成语义**

跨包请求在 **S2、成功响应和 S3 写入之前**触发：

```text
WaitSafe → FreezeDrain → Recheck → CaptureSend
         → WaitSave → Clear → HandoffRetry
```

safe-old 同样进入保存流程。只有 `lower_equal` 能证明当前完整 image 已在 L2 时，才可免去重复发送；每次实际 store 都清除此证书。因此重新 Acquire 后不会陷入反复 push 的循环。

保存完成采用匹配事务的晚到 ReleaseAck，不能使用当前仅表示 snapshot 完成的 `wb.resp`。

replay 改为：

```text
RPQ head → issue → inflight → 实际完成 → replay_done → pop/free SDQ
```

第一版限制每个 MSHR 的 write domain 只包含一个 package，并让 store miss/upgrade 完成后再发年轻 store，消除现有 `111→112→111` 混写。LSU 拒绝请求走 nack/STQ 重试；replay 拒绝请求保留 RPQ/SDQ。

**3. L1→L2 保存链与 barrier**

speculative L1 eviction 可以进入 L2 staging buffer，随后执行：

```text
BufferIncoming → CheckVersion → SaveOld
               → WaitOuterAck → Reacquire
               → CommitIncoming → Ack/ProbeDone
```

L2 必须先把 resident safe predecessor 保存到 DRAM，再覆盖 bank/目录。这直接针对已有 seq4 被 seq6 覆盖、此前没有同址 outer C 的反例。

新增 `outer_equal` 和 `parent_in_dram`，分别表示“当前 image 已保存”和“当前版本的 predecessor 已保存”。二者不能合并。

ReleaseData 与 **ProbeAckData** 都进入这套 admission；后者当前直写 BankedStore 的旁路必须合并。SourceD 完成最后真实 bank write、目录提交和权限准备后，由独立 ACK queue 确认；不能卡住首拍等待最后一拍，否则会自锁。

复用现有 SourceC barrier、watermark 和 close 服务，对**最终选中的请求，包括 release 拍**检查安全性；unsafe 请求停留，safe 保存与必要响应继续前进。

**4. 关键 invariant**

- 成功 store 恰好完成一次，不被旧 refill 丢失。
- Q 覆盖 P 前，P 已 safe，且当前完整 P 有匹配的下层保存证书。
- speculative Q 提交到 L2 前，其 safe predecessor 已保存到 DRAM。
- speculative/UNKNOWN 数据不能通过 timeout、统计 reset 或 barrier release 旁路进入 DRAM。

**5. 实施拆分与验证**

| Phase | 实现范围 | 关键验证与波形 |
|---|---|---|
| **1：ownership** | owner/generation、clear/drain、统一 replay gate、实际完成 token、完整 refill commit | 重现 clear/refill race；观察 S1/S2 授权、S3 fire、owner、RPQ issue/done、SDQ/STQ token；检查 exactly-once |

**6. deadlock 评审结论**

仅增加 stall 不足以保证进度：当前 close 需要 ROB empty，而 unsafe L2 victim 可能阻塞 ROB load，形成循环依赖。

推荐在 L2 边界内增加有界 victim 暂存及完成额度，配合提前 pressure-close；等待 watermark 时不占 WB、SourceD 或整个 set 的执行资源。**暂存容量、credit 上界和 checker/PTW 依赖闭包仍需核对，文档中的候选容量不是已证明的无死锁保证。**
