**一、跨包 Store 覆盖**

在 DCache 真正写入前读取旧 line 的 provenance：

```text
old_tracked
&& old_seq != 0
&& new_seq != 0
&& old_seq != new_seq
&& old_seq > safe_watermark
```

满足条件时：

1. 暂存新 Store 的地址、数据、mask、way、包序号。
2. 保存被覆盖 line 的完整旧版本。
3. 请求旧包完成封包并等待 `safePacketWatermark` 覆盖旧包。
4. 先把旧版本作为“安全前驱”发送到 L2。
5. L2 接受前驱后，才允许新包 Store 覆盖 L1。

同包重复写不产生屏障。旧包已安全时不等待水位，但仍需先发送安全前驱。

这里不能直接把普通 `ReleaseData` 当成复制操作，因为它会改变 L1 所有权。建议使用独立的 `SafePredecessor` sideband，或者扩展 L2 目录语义。

**二、L2-DRAM 屏障**

L2 在 SourceC request 即将被接受时检查：

```text
dcache_originated
&& dirty
&& tracked
&& packet_seq > l2_safe_watermark
```

满足条件时：

1. SourceC request 暂不 fire。
2. L2 保留 victim 和其 metadata，不能提前清除目录项。
3. 通过跨时钟域请求通知 BOOM，携带 `{packetSeq, lineAddr, epoch}`。
4. BOOM 完成目标包封存后，L2 等待同步后的 Gray watermark。
5. 目标包安全后，释放 SourceC request，才允许向 DRAM 写回。

L2 的 line provenance 需要随内部 line/M​​SHR 保存，不能依赖现有 16-entry L1-L2 CAM 作为长期存储。

**三、避免封包死锁的核心状态机**

不能先拉高 BOOM 的全局 stall，再等待封包。正确顺序应是：

```text
IDLE
  -> BARRIER_REQUESTED
  -> PACKAGE_DRAIN
  -> PACKAGE_CLOSED
  -> HARD_STALL
  -> WAIT_SAFE
  -> RELEASE
```

具体含义：

- `BARRIER_REQUESTED`：锁存 L2 请求或跨包覆盖请求。
- `PACKAGE_DRAIN`：
  - 暂停取指/派发新的相关指令；
  - 允许当前 ROB 继续提交；
  - 允许 GH_BUF 接收并排空当前包数据；
  - 禁止新的包切换和新的相关 Store。
- `PACKAGE_CLOSED`：
  - 强制 R_IC 关闭当前包；
  - 触发 R_RSU 的 CPS/ECP 传输；
  - 等待数据包、ARF/CPS 和包序列都被 CDC 路径接受；
  - 收到明确的 `package_sealed(seq)` 应答。
- 只有收到 `package_sealed` 后，才允许产生 `barrier_stall` 并进入 `HARD_STALL`。
- `HARD_STALL` 期间，Checker、GHM、结果 CDC 和水位推进必须继续运行。
- 水位覆盖目标包后释放 L2 request 或暂存 Store。

必须为紧急封包预留至少一个 GH_BUF/ARF-CPS/控制队列容量。若容量不足，不能静默丢弃 line，也不能进入无法封包的硬 stall；应继续保持请求未接受并报告 overflow。

**四、失败路径**

如果目标包返回 `FAIL` 或 `CANCELLED`，连续 PASS 水位不会推进。功能屏障不能无限等待，应进入明确的恢复路径：

- 回滚/重新执行当前推测状态；或
- 终止本次受检会话并报告不可用。

不能把失败包当成安全包释放到 DRAM。

**五、统计口径**

现有 0--106 ABI 和新增 107--127 统计保持不变。监控统计与真实功能 stall 的时间必须分开：

- L2 周期仍使用 L2 本地时钟，不能与 BOOM `csr_cycle` 直接相减。

2. **L2 要把尚未安全的 dirty victim 写往 DRAM。** 先阻止该 victim 被 SourceC 接受，发起封包请求；等 BOOM 确认快照已被接受后，才允许 hard stall。L2 随后等安全水位覆盖该包，再放行 victim。这样封包发生在 BOOM stall 之前。

监控统计继续默认开启，且不驱动功能路径的 ready、valid 或 stall；真实屏障由参数选择，默认关闭。真实屏障使用带 bank 和包序号的独立 sideband，不复用 TileLink ownership 消息。跨时钟域时，请求、序号和确认需要保持稳定并通过握手传递；多个 L2 bank 的请求需要仲裁，不能让一个无 bank 标识的确认同时作用于多个请求。FAIL/CANCELLED 不得推进安全水位或伪装成成功；在回滚实现前，应通过独立错误路径尽快报告并结束当前测试流程。
