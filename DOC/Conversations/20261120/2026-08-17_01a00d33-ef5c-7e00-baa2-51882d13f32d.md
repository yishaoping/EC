## Important Hardware Facts Captured

- 136-bit lane:
  - `[135:128]` header
  - `[127:0]` payload
  - header `[7]` enable, `[6:3]` checker target, `[2:0]` type
- Types:
  - 1 load
  - 2 store
  - 3 CSR
  - 4 branch/jump
  - 5 RoCC writeback
  - 7 context, generated by `R_RSU`, not `GH_BUF`
- Two 136-bit lanes form a 272-bit group.
- GHM appends 32-bit sequence and 1-bit valid, producing 305 bits.
- Context input:
  - `[152:145]` ECP route
  - `[144:137]` CPS pidx
  - `[136:128]` 9-bit context index
  - `[127:0]` data
- GHM removes ECP routing metadata and produces:
  - valid + sequence + CPS pidx + context index + data = 178 bits
- Same boundary snapshot serves as CPS for the new checker and ECP for the old checker.
- Load packet data is replay input; explicit load check compares address only.
- Store explicitly compares address and size-masked data.
- CSR/RoCC results are replay/writeback inputs rather than direct equality checks.
- Branch packets drive `R_BJLR` reserve/commit/rollback behavior.
- Final errors aggregate:
  - `R_ELU` load/store errors
  - `R_RSUSL` ARF/FARF mismatch
  - CSR shadow mismatch
- Result format:
  - `{valid, status[1:0], sequence[31:0]}`
  - PASS=0, FAIL=1, CANCELLED=2
- BOOM checker release is tied to sequenced result dequeue in the BOOM clock domain.
